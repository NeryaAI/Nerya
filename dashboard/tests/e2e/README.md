# Nerya E2E (Playwright) Test Suite

Implements the test plan in `Nerya/docs/nerya-prompt-test-plan.md` using
Playwright against the live Next.js dashboard (`:3001`) and the Nerya
E2E runtime (`:18318`). The normal local runtime often uses `:18317`; the
E2E suite intentionally uses `:18318` so it does not silently reuse the
operator's real workspace.

**Two complementary modes**:

1. **CSV-driven** (`csv-runner.spec.ts` + `cases.csv`) — easy to extend by
   non-coders, produces per-case screenshots + logs + CSV summary. **Start here.**
2. **Typed spec files** (per-group `*.spec.ts`) — fine-grained assertions
   for the hard cases (regex on `main.py`, journal cross-checks).

Both share the same `fixtures.ts`, `global-setup.ts`, and isolated
`.nerya-test-workspace/` directory — your real workspace is never touched.

Prompt E2E defaults to `NERYA_PERMISSION_MODE=yolo` so unattended cases do not
stall on routine tool approvals. Use `NERYA_PERMISSION_MODE=default` only when
you are explicitly testing the approval UI/path.

## Install

```bash
cd Nerya/dashboard
npm install -D @playwright/test
npx playwright install chromium
```

The npm scripts are already wired in `package.json`:

```bash
npm run test:e2e            # everything (full plan)
npm run test:e2e:csv        # CSV-driven only
npm run test:e2e:smoke      # ~10 min smoke
npm run test:e2e:headed     # visual debug (single worker)
npm run test:e2e:reset      # safe-wipe the test workspace
npm run test:e2e:reset:full # nuke + recreate the test workspace
```

## Isolated test workspace

`global-setup.ts` automatically:

1. Creates / reuses `Nerya/dashboard/.nerya-test-workspace/` (overridable
   via `NERYA_WORKSPACE`).
2. Drops a minimal `nerya.yml` with `live_trading_enabled: false`.
3. Invokes `Nerya/tools/reset_workspace.py` to wipe ephemeral artifacts
   (proposals, journals, inbox, schedules, teams, strategies, agent
   tasks, dead-letter…) while **preserving**:
   - `vault/` (encrypted secrets)
   - `accounts/` (configured venues)
   - `subagents/` (custom roles you authored)
   - `skills/installed/`, `scripts/approved/`
4. Pings runtime `/health` + dashboard root to fail fast if servers
   aren't running.
5. Verifies both the direct runtime URL and the dashboard proxy target
   are bound to the same isolated workspace and are not using the default
   `provider: mock` agent tier. Prompt E2E is allowed to run on mock only
   when `NERYA_E2E_ALLOW_MOCK_LLM=1` is set explicitly.

**Important**: when starting the Nerya runtime for the tests, point it
at the SAME workspace:

```bash
# One-time: clone real LLM provider config + vault into the isolated workspace.
python tools/prepare_isolated_test_workspace.py \
  --target dashboard/.nerya-test-workspace \
  --verify

# Terminal 1 (runtime) — use the test workspace!
NERYA_WORKSPACE="$(pwd)/dashboard/.nerya-test-workspace" \
  python -m nerya.cli.app serve --workspace "$(pwd)/dashboard/.nerya-test-workspace" --port 18318 --no-dashboard
```

Skip the reset (e.g. when iterating locally) with
`NERYA_TEST_SKIP_RESET=1 npm run test:e2e:csv`.

For an isolated workspace per OS user / CI job, set
`NERYA_WORKSPACE=/tmp/nerya-test-$USER-$BUILD_ID`.

### Context-full request logs

Normal per-case logs stay compact under `dashboard/test-results/logs/`.
When a failure needs prompt-level analysis, enable full LLM request logging:

```bash
NERYA_CONTEXT_FULL_LOG=1 npm run test:e2e:csv
```

or set `llm.context_log_mode: full` in the isolated workspace `nerya.yml`.
The runtime appends redacted records to:

```text
<NERYA_WORKSPACE>/dev_logs/llm_context_full.jsonl
```

Each LLM call writes `request`, `response`, and `error` records under one
`call_id`. Agent loop records also expose top-level correlation fields such as
`session_id`, `turn_id`, `iteration`, completed/successful tool names,
required next tools, LLM retry attempt, sent message/tool counts, safety-retry
state, and remaining wall time. The request record still contains the same
metadata under `request.metadata` and is captured before provider formatting
with the canonical `system`, `messages`, `tools`,
`tool_choice`, token/reasoning settings, deadline, provider, model, and safe
tier config. Values pass through the display redactor before writing, so
secrets and common vendor-token shapes are masked while the full prompt/tool
context remains inspectable.

## Run

### Pre-requisites (two terminals)

```bash
# Terminal 1 — isolated E2E runtime
cd Nerya
python tools/prepare_isolated_test_workspace.py \
  --target dashboard/.nerya-test-workspace \
  --verify
python -m nerya.cli.app serve --workspace dashboard/.nerya-test-workspace --port 18318 --no-dashboard

# Terminal 2 — dashboard
cd Nerya/dashboard
NERYA_API=http://127.0.0.1:18318 npm run dev:e2e   # :3001
```

### Tests (third terminal)

```bash
cd Nerya/dashboard

# All tests
npm run test:e2e

# Smoke only (~10 min)
npm run test:e2e:smoke

# A single group
npx playwright test C-strategies

# Single case (filter by title)
npx playwright test -g "C1 — script BTC"

# Visual debug
npm run test:e2e:headed
```

### Auto-start runtime + dashboard (CI)

```bash
PLAYWRIGHT_AUTOSTART=1 npx playwright test smoke
```

## Troubleshooting — read this if a run produces opaque timeouts

A May-2026 run failed every chat case with 120 s `data-turn-loading="true"`
timeouts. Postmortem in `task_plan.md` / `notes.md` (same folder). Root causes
and the guardrails now in place:

| Symptom | Root cause | Guardrail / fix |
|---------|-----------|-----------------|
| Every `POST /api/proxy/agent/run_turn` → **500** (GETs all 200) | Corrupted Next.js `.next` dev build (`Cannot read properties of undefined (reading 'call')`, RSC client-manifest misses) | `global-setup` now probes the **POST** proxy and aborts with a fix hint; `route.ts` converts unexpected throws into a labeled JSON 502 |
| `.next` corrupts mid-run | webpack FS-cache `EPERM/ENOENT` renames on `.next/cache/*.pack.gz` (concurrent procs / AV on Windows) | `npm run dev:e2e` cleans `.next` and disables the webpack FS cache (`NERYA_E2E=1`) |
| Tests "pass reset" but hit real data; 100s of stray approvals | **Runtime bound to the wrong workspace** (`~/.nerya`, not `.nerya-test-workspace`) — it's started separately so `NERYA_WORKSPACE` never reaches it | `global-setup` now hard-fails unless `NERYA_E2E_ALLOW_WORKSPACE_MISMATCH=1` is set explicitly |
| Replies look like `[mock] you said: ...` | Dashboard proxy or runtime is on a workspace whose `llm.tiers.*.provider` is still `mock` (often an old `.nerya-playwright-workspace`) | `global-setup` now checks both direct API and `/api/proxy` and aborts unless `NERYA_E2E_ALLOW_MOCK_LLM=1`; restart dashboard with the correct `NERYA_API` |
| Turns hang / never finish | tool calls create **approvals** nobody resolves; provider key/quota is unavailable; OR dev `http.jsonl` grew to 100s of MB | `global-setup` probes the real messages backend, warns on pending approvals + dev-log bloat; clear with `curl -X POST :18318/dev/clear`; use a non-gating permission mode / auto-approve for unattended runs |
| Opaque 120 s waits | fixture only waited for `loading=false` | `waitAssistantText` now races completion vs **error card** vs timeout and prints proxy/workspace/approval diagnostics on stall |

### Correct startup for E2E (Windows / bash)

```bash
# Terminal 1 — runtime, bound to the ISOLATED workspace (critical!)
cd Nerya
python tools/prepare_isolated_test_workspace.py \
  --target dashboard/.nerya-test-workspace \
  --verify
NERYA_WORKSPACE="$(pwd)/dashboard/.nerya-test-workspace" \
  python -m nerya.cli.app serve --workspace "$(pwd)/dashboard/.nerya-test-workspace" --port 18318 --no-dashboard

# (one-time, if the runtime's dev log is huge)
curl -X POST http://127.0.0.1:18318/dev/clear

# Terminal 2 — dashboard, clean build + cache disabled
cd Nerya/dashboard
NERYA_API=http://127.0.0.1:18318 npm run dev:e2e   # cleans .next, NERYA_E2E=1, :3001

# Terminal 3 — tests
cd Nerya/dashboard
npm run test:e2e:smoke
```

If `global-setup` aborts, it tells you exactly which gate failed (broken POST
proxy, workspace mismatch, or dev-log bloat) — fix that before the long run.

## CSV-driven workflow (recommended for non-coders)

### 1. Add a case

**Option A** (preferred): edit `Nerya/docs/nerya-prompt-test-plan.md`,
add a new `### <id>. <title>` section with a Markdown table containing
a `**Prompt**` cell. Then regenerate:

```bash
cd Nerya && python tools/extract_cases.py
# Wrote 161 cases to dashboard/tests/e2e/cases.csv
```

`extract_cases.py` reads the plan, applies per-id overrides (defined
inline in the script) for things like `must_not_contain` regex on
secrets, `api_check` mini-DSL, and stricter timeouts. Anything that
needs more than the plan auto-derived defaults should be added to the
script's `OVERRIDES` dict alongside the plan edit.

**Option B**: hand-edit `cases.csv` directly. Header:

```
id, group, priority, prompt, must_contain, must_not_contain,
api_check, timeout_ms, reset_before, notes
```

- **`id`** unique (e.g. `C-AT15`). Mirrors the plan ID.
- **`prompt`** Natural language, exactly what a real user would type.
  Avoid commas (CSV breaks); use spaces / `+` / `&` instead.
- **`must_contain`** Regex. Empty = skip. Case-insensitive.
- **`must_not_contain`** Regex. **CRITICAL** for security cases — used
  literally case-sensitive so secrets must not slip through.
- **`api_check`** Mini-DSL (`:`-separated). Supported keys:
  | Key | Effect |
  |-----|--------|
  | `strategy_proposal_kind=<kind>:<needle>:execution_mode=<m>:main_py_contains=<txt>` | Verifies strategy proposal + execution_mode + main.py content. `main_py_contains` may repeat. |
  | `proposal_kind=<kind>:metadata_contains=<txt>` | Generic proposal exists, metadata contains text |
  | `account_created=<id>:venue=<venue>` | Account exists with venue |
  | `account_matching=<venue>:mode=<mode>` | At least one account exists with venue/mode |
  | `schedule_session_kind=<kind>` | At least one schedule with kind `agent`/`script` |
  | `team_template=<template>` | At least one team run with that template |
  | `wallet_provider_has=<id>` | `/wallet/providers` includes id |
  | `exchange_provider_has=<id>` | `/exchanges/providers` includes id or alias |
  | `gateway_platform_has=<id>` | `/gateway/platforms` includes id |
  | `credential_schema_okx_has=<field>` | OKX credential schema includes field |
  | `task_created=true` | `/agent/tasks` has at least one task |
  | `team_run_exists=true` | `/teams/runs` has at least one durable team run |
  | `tool_used=<name>` | Latest turn contains a successful (`ok=true`) tool result for the named native tool. Multiple names may be separated with `|` or `,`. |
  | `tool_not_used=<name>` | Latest turn contains no observed tool use/result for the named native tool. Multiple names may be separated with `|` or `,`. |
- **`timeout_ms`** Per-case timeout (driver adds 30 s buffer).
- **`reset_before`** `1` wipes ephemeral runtime state plus
  agent-authored memory/profile recall before this case. This is enabled
  by default for the isolated CSV runner so memory cases do not poison
  later strategy cases; set `NERYA_RESET_PER_CASE=0` only for one-off
  local debugging. The reset preserves vault/accounts.

### 2. Run just your case

```bash
# Run one
NERYA_CASES_ONLY=C-AT15 npm run test:e2e:csv

# Filter regex (e.g. all C-AT* deep cases)
NERYA_CASES_FILTER='^C-AT' npm run test:e2e:csv

# Custom CSV path
NERYA_CASES_CSV=./my-cases.csv npm run test:e2e:csv
```

### 3. Read outputs

```
test-results/
├── screenshots/<id>.png         # full-page screenshot at end of each case
├── logs/<id>.jsonl              # step-by-step event log (timestamped)
├── logs/<id>.reply.txt          # full assistant reply
├── summary.csv                  # one row per case: pass/fail/duration/api_check
├── results.json                 # Playwright JSON reporter
└── ../playwright-report/index.html
```

`summary.csv` opens in Excel/Numbers for at-a-glance review. Failed
cases also save their last-known screenshot (even mid-fail).

## Conventions

- **All tests must use `paper` mode**. The suite never sets `live_trading_enabled=true`.
- **Selectors prefer roles/text/aria-label** (not unstable Tailwind classes).
  - Chat input: `page.locator("textarea").first()`
  - Send button: `page.getByRole("button", { name: /^(Send|发送)$/ })`
- **API truth-source**: every UI assertion is paired with at least one
  `/api/proxy/*` (or direct `:18318`) cross-check so a fake "looks-good"
  reply alone can't pass.
- **Negative tests** (B7/B8, F7, L*) explicitly assert that prohibited
  behavior *did NOT* happen (no fabricated CryptoPanic fields, no
  protected-scope mutation, no plaintext secret echo, no live fills).

## Mapping to the test plan

The grouping above mirrors `Nerya/docs/nerya-prompt-test-plan.md`. Each
case in this suite carries an inline comment referencing the plan ID
(e.g. `C5 — agent_task BSC meme strategy`). When you add more cases:

1. Pick the plan ID from the markdown.
2. Add a `test("CXX — ...", ...)` block.
3. Assert both the **chat reply text** (intent) **and** a runtime side
   effect (proposal, schedule, journal, account).

## Known soft assertions

These tests are tolerant where the runtime intentionally varies:

- `GX10` accepts both `ok=true` and `venue-not-supported` (CCXT version
  may or may not include `hyperliquid` as a first-class alias).
- `GX2` accepts either an IBKR chain OR an honest "gateway missing"
  message, since not every dev box runs TWS.
- `H9` checks shape (`ready: boolean`), not whether keys are configured.

These are documented in each spec's comments so reviewers don't tighten
them blindly.

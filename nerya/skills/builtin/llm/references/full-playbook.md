# LLM helpers playbook

This skill is for cases where the *right answer* is a piece of text
generated by an LLM with a tightly-scoped prompt — summaries,
restylings, translations, captions. The agent is an LLM, but using
itself for these tasks is wasteful: a one-shot helper run is faster,
cheaper, and easier to audit.

## When to use a one-shot helper

- The output is short and self-contained.
- The transform does not require the agent's broader context (no
  tool use, no memory of prior turns).
- The user wants a specific *form* (e.g. "rewrite in 3 bullet
  points") rather than a *decision*.

If the task needs the agent's own reasoning, planning, or tool use,
do it yourself.

## Choosing tone, length, format

State all three before calling the helper:

- **Tone**: formal / friendly / playful / clinical / matter-of-fact.
- **Length**: word or sentence cap; "as short as possible" is *not*
  a length, give a number.
- **Format**: bullets / paragraph / markdown / JSON.

Never ask the helper to "be creative" without scaffolding — you'll
get a wall of generic prose. Constraints make creativity legible.

## Bundled scripts

| Script | Purpose |
|---|---|
| `scripts/summarise.py` | Summarise text → bullets / paragraph / TL;DR. |
| `scripts/restyle.py` | Rewrite text in a specified tone / register. |
| `scripts/translate.py` | Translate between languages with optional glossary. |
| `scripts/draft.py` | Draft a short artefact (commit message, release note, subject line). |

Each script accepts JSON payload via `--json` / `--payload-file` /
stdin and prints the resulting text on stdout.

## Failure modes

- **Untruncated inputs.** Helpers silently fail when fed too much
  context. Pre-trim or chunk before calling.
- **No tone specified.** You will get the model's default voice,
  which is rarely what the user wanted.
- **Re-using a stale helper output.** If the source text changes,
  re-run; don't hand-edit a stale summary.
